# CityScooter 协议 v1

v1（2026-11-07）在 v0 上只**加**消息：板子可以发出拳 `pu`、按铃 `bl`；游戏会发 `ko`、`warn:…`、`turn:…`。11/8 又加了西澳警察（通缉星级、警车追捕、直升机撒网和狙击）：板子可以发投降 `sur`，游戏会发 `wanted:N`、`chase:…`、`cop:N`、`heli:…`、`inc:…`、`arrested`、`busted`、`lost`。11/9 加了 **v0.4 无线竞速**：板子可以发 `race:名字:组号` 和 `rx:<收到的无线消息>`，游戏会发 `pos:距离:车道`、`fin:秒数`（见下面"无线竞速"一节，方案见 `docs/radio-race.md`）。11/10 加了**道具赛**（无线竞速 v2）：板子可以发 `use`，游戏会发 `item:名字`、`hit:名字`、`blocked:名字`、`tx:<无线消息>`，无线上多了 `i:` 消息；比赛模式里警察类的 `do:` / `open:` 照常执行（见下面"道具赛"一节，方案见 `docs/item-race.md`）。v0 的学生代码不用改，不认识的消息会被跳过。

学生写的 micro:bit 程序和游戏之间只说这一种"话"。每条消息一行，ASCII 文本，以换行 `\n` 结尾。
USB 串口波特率 115200。v0 只用于 USB 直连和模拟器；无线（radio）版在第 2 周基于同样的消息再设计。

代码里的定义：`Assets/_Project/Scripts/Protocol/Messages.cs`，解析规则和单元测试见同目录与 `Assets/_Project/Tests/EditMode/`。

## micro:bit → 游戏

| 消息 | 含义 | 学生代码写法（MicroPython） |
|---|---|---|
| `st:-35` | 转向，-100（最左）到 100（最右），超出会被截断；允许小数 | `print("st:" + str(steer))` |
| `jp` | 跳一下（在空中重复发不会多跳） | `print("jp")` |
| `br` | 刹车。每条维持 0.3 秒，按住就每个循环发一次 | `print("br")` |
| `hi:v2` | 报告板子版本（可选，游戏显示用） | `print("hi:v2")` |
| `pu` | **v1** 出拳：把前方左右 2.5 m 内最近的纸箱、垃圾桶、锥桶打飞，打中游戏回 `ko`。冷却 0.4 秒，冷却中发的不算。人、车、路障打不动 | `print("pu")` |
| `bl` | **v1** 按铃：前方 30 m 内的行人让到一边，头上冒"!" | `print("bl")` |
| `do:事件` | **v1** 让游戏发生它自己的事件（**v0.3** 加了 `ramp`：在你这条车道前方看不到的地方放一个跳台，落地区的障碍会清掉）：`chase`（警方追击）、`stars:0`～`stars:5`（设定通缉星级，0 是警察放弃）、`heli`（直升机，至少 3 星）、`calm`（警察放弃）、`turn:L` / `turn:R`（前方安排一个弯）、`car`（对向车）、`slowcar`（前面的慢车）、`roadworks`（路政）、`police`（警察拦路）、`crossing`（行人过马路）、`manhole`（窨井）。骑行中每块板每秒最多 1 次；两局之间（开局画面、撞车后的结算画面）发的先记下来，下一局开始 0.4 秒后执行，同一种事件只记最后一次；路段事件放在前方看不到的地方，不会放在大马路的过渡路段上。之后照常收到 `chase:1`、`wanted:N`、`warn:car` 这些消息 | `print("do:chase")` |
| `open:事件` | **11/9** 每一局开头都让游戏发生这个事件，事件和 `do:` 一样（`open:stars:5`、`open:chase`、`open:turn:L`……）。用在程序的"开始时"：程序只在板子启动时跑一次，但撞车后按 A 是新的一局，`do:` 只管一次。**程序要大约每秒再发一次**（跟 `hi:` 一起，积木自动这样做）：游戏第一次听到某个事件时，如果正在骑就马上执行，否则屏幕提示 "(every ride)"；之后每一局开始 0.4 秒后执行。同一种事件以最新的数字为准。板子还在说话、但超过 3 秒没再发这个事件（换了新程序），游戏就忘掉它；拔掉的板子不算数，插回来接着算。比赛模式里的处理见 `docs/item-race.md` | `print("open:stars:5")` |
| `say:party` | **v1** 让游戏说一个自己的词：游戏把 `party` 转发给**所有**连着的板子（包括发的这块），并在屏幕上显示是谁说的。规则：一个词，字母、数字和 `_ - ! ?`，最长 16 个字符；不能是游戏自己的消息（`crash`、`gift`、`go` 等，也不能带冒号），否则监视器会提示格式不对；每块板每秒最多 2 次，多的不转发 | `print("say:party")` |
| `bo` | **v1** 加速：2 秒内速度提到上限的 1.35 倍。冷却 6 秒，冷却中发的不算 | `print("bo")` |
| `toon:1` / `toon:0` | **v1** 卡通模式开/关。开着时撞到行人不算撞车：人"BOING!"一声飞出去，你减速，出拳也能把人打飞；关着时撞人就是撞车。游戏记住最后一次收到的值（只发 `toon` 也算开）。程序一开始就发的那条可能游戏还没收到，所以放在循环里或按钮里发。11/10 起积木生成的代码把它记在 `toon_mode` 里，跟 `hi:` 一起每秒再发一次，所以放在"开始时"里也可靠，刷新页面后也不会丢 | `print("toon:1")` |
| `trick` | **v0.3 跳台** 在空中做特技：从跳台飞起来以后（收到 `air:1` 之后）第一次是转体 SPIN，第二次是后空翻 FLIP，轮流来，每个 0.6 秒，各加 50 分；一次飞行里做完 2 个以上，安全落地时每个再加 25 分（COMBO）。正在做的时候再发一条会排在后面（最多排 1 条）。落地时特技还没做完：不算撞车，显示 SKETCHY!，这一个不加分。在地上、普通小跳里发了不算。3 秒内发了 6 条以上（在地上发的也算）就会"头晕"，3 秒内不能做特技，所以放进 forever 里一直发没用。`trick:1` 也认。键盘 `Q` | `print("trick")` |
| `start:kingspark` | **v0.3 场景（11/9）** 选出发场景：id 和 `zone:` 一样（v0.4 起共 15 个，见下面 `zone:` 一行），空格、大写和其他符号会被去掉，所以 `start: Kings Park` 也认。在开局画面上马上换过去（最多每 0.3 秒换一次）；骑行中或撞车画面上发的，这一局照常，下一局从那里出发。游戏记住最后一次收到的值，同一个值重复发不会重建赛道。不在路线上的 id 不理（网页监视器会列出可用的 id）。积木"start rides in [Kings Park]"大约每秒会再发一次，因为程序一开始就发的那条游戏可能没收到 | `print("start:kingspark")` |
| `sur` | **v1 警察（11/8）** 投降：被警察追的时候马上靠边停车（自动刹车到停下），停稳 1.5 秒后 ARRESTED。没被追时发了不算。`sur:1` 也认 | `print("sur")` |
| `race:AMY:12` | **v0.4 无线竞速（11/9）** 我要比赛：名字和组号（`radio.config(group=…)` 的那个数，0～255）。名字只留字母和数字，转成大写，最多 5 个字符（`Amy-2` → `AMY2`）；空名字或组号不对，监视器提示格式不对。每秒发一次（跟 `hi:` 一起）。游戏收到第一条就进入比赛大厅，**超过 10 秒没收到就回到普通模式** | `print("race:" + NAME + ":" + str(GROUP))` |
| `rx:p:BEN:120:-2` | **v0.4 无线竞速** 板子把收到的无线消息原样转给游戏：`rx:` 后面就是 `radio.receive()` 得到的内容。游戏只认 `p:`、`f:`、`go:` 三种（见下面"无线竞速"一节）和道具赛的 `i:`（见"道具赛"一节），其他内容不理，但监视器照样显示 | `print("rx:" + heard)` |
| `use` | **道具赛（11/10）** 用掉手里的道具（比赛里骑过道具箱拿到的，游戏先发过 `item:名字`）。**道具不会自己用**，程序发了 `use` 才用。手里没有道具时发了不算，网页监视器提示一次。每个道具的效果见 `docs/item-race.md` | `print("use")` |

- 推荐循环 `sleep(50)`，也就是每秒 20 次左右。转向超过 0.5 秒没更新，游戏会把转向归零（拔线、程序报错时车不会一直往一边跑）。
- 一帧内收到多个 `jp` 只算一次。轮询写法 `is_pressed()` 会每秒发几十个 `jp`，游戏不会出错，但串口监视器会把这个次数显示出来，第 4 课正好用来讲事件写法和轮询写法。
- **任何不认识的行都不算错误**：学生自己的 `print`、Python 报错（Traceback）都原样显示在串口监视器里。
- 格式宽松：大小写不敏感，冒号两边可以有空格（`ST : 20` 也认）。`st:abc` 这种值不对的会标成"格式不对"，监视器给提示。

## 游戏 → micro:bit

| 消息 | 什么时候发 |
|---|---|
| `go` | 新的一局开始 |
| `crash` | 撞车 |
| `gift` | 捡到礼物 |
| `spd:0` … `spd:9` | 实际速度相对当前速度上限的档位，变化时才发，每秒最多 5 次；上限可随本局进度增长 |
| `ko` | **v1** 出拳打中了 |
| `boing` | **v1** 卡通模式下撞飞了一个人 |
| `tired` | **v1** 拳出完了（最多连出 3 拳，每 1.2 秒恢复 1 拳），这时发的 `pu` 不算；每秒最多发一条 |
| `warn:car` / `warn:ped` / `warn:hole` | **v1** 自己这条路上（左右 1.3 m 内）前方有车、有人、有坑：25 m 或 1.5 秒车程内，取远的那个。同一个东西 8 秒内只发一次，所有警告合起来每秒最多 4 条（V1 的串口缓冲小） |
| `turn:-1` / `turn:1` / `turn:0` | **v1** 路开始往左弯、往右弯、回到直道（假拐弯，路在物理上还是直的；难度 3 级以后拐弯会把人往弯外推一点，要往弯里转向） |
| `wanted:0` … `wanted:5` | **v1 警察** 通缉星级，变了才发。打警察、打警车一次加 1 星（最多 5 星）；甩掉警察或者一阵子不再打警察会掉星。新的一局开始时如果不是 0，会在 `go` 之后补发 `wanted:0` |
| `chase:1` / `chase:0` | **v1 警察** 警车开始追你 / 追捕结束（甩掉了、被抓了、撞车了） |
| `cop:0` … `cop:9` | **v1 警察** 追你的警车在多远：大约每 10 m 一档，0 就是贴着你，9 是很远或者暂时没有警车。只在被追时发，变化时才发，每秒最多 3 条。追捕结束后不再发：自己的程序在收到 `chase:0` 或 `go` 时把它当成 9（积木生成的代码会自动这样做） |
| `heli:1` / `heli:0` | **v1 警察** 警用直升机来了（3 星以上）/ 走了 |
| `inc:L` / `inc:C` / `inc:R` | **v1 警察** 直升机要撒网的靶圈出现了、或者狙击红点锁定了：在你左边 / 就在你身上 / 在你右边。网从靶圈出现到落下至少 0.8 秒，`inc:C` 时往旁边躲（网也可以刹车躲）就躲得开；红点锁定后闪 0.7 秒（5 星 0.55 秒）开枪，要往旁边挪开。注意大写字母 |
| `arrested` | **v1 警察** 被抓（ARRESTED）：被追时停下来了（刹到很慢、或者发了 `sur`），或者警车在旁边贴着你 1.5 秒，或者被直升机的网罩住（"NETTED!"）。这一局结束，紧跟在 `crash` 后面发 |
| `busted` | **v1 警察** BUSTED：被警车撞了，或者被直升机上的狙击手打中（漫画式摔下车，没有血）。这一局结束，紧跟在 `crash` 后面发 |
| `air:1` / `air:0` | **v0.3 跳台** 从跳台飞起来了 / 落地了（或者在空中撞车、掉进水里，这时 `air:0` 在 `crash` 前面）。每次飞行各发一次。普通跳（`jp`）只飞 0.65 秒，**不发**；只有从跳台起飞，或者预计能飞 0.8 秒以上的（比如在高平台上起跳）才发（`GameTuning.airMessageMinSeconds`） |
| `land:ok` / `land:trick` | **v0.3 跳台** 安全落地，紧跟在 `air:0` 后面：这次飞行里至少做完 1 个特技是 `land:trick`，否则 `land:ok`。掉进缺口（SPLASH!）、落在车上撞车时没有 `land:` |
| `lost` | **v1 警察** 甩掉警察了（LOST THEM!）：星级掉到 0。加分只算打警察挣来的星（每颗 100），`do:stars` 这类程序给的星不加分 |
| `zone:uwa` … | **v0.3 场景** 你在哪个场景（沿 UWA → 珀斯市中心的真实骑行线）：一局开始时在 `go` 后面发一次出发的场景，之后每骑进下一个场景发一次（几百米一次，很少）。id 按路线顺序：`uwa`（UWA）、`matilda`（Matilda Bay）、`kingspark`（Kings Park）、`westperth`（West Perth）、`cbd`（Perth CBD）、`quay`（Elizabeth Quay）、`mountsbay`（Mounts Bay Road）；**v0.4 南线**接着是 `canningbridge`（Canning Bridge）、`murdoch`（Murdoch）、`cockburn`（Cockburn Central）、`aubingrove`（Aubin Grove）、`kwinana`（Kwinana）、`wellard`（Wellard）、`rockingham`（Rockingham）、`warnbro`（Warnbro），走完再回到 `uwa`。只有小写字母。屏幕上同时显示 `ENTERING KINGS PARK` |
| `pos:1234:-2` | **v0.4 无线竞速** 只在比赛模式里发（收到过 `race:`）：我现在的距离（米，整数，从起点算）和车道（米，整数，路中间是 0，左负右正）。比赛中（包括倒数）每秒 4 次；在大厅、结算画面和冲线 10 秒以后每秒 1 次 `pos:0:0`，这样同组的人能在名单里看到你。板子把它广播成 `p:名字:1234:-2` |
| `fin:72.35` | **v0.4 无线竞速** 我冲线了，用时（秒，两位小数，从 GO 算起）。冲线后每 0.5 秒发一次，持续 10 秒，这 10 秒里**代替** `pos:`。板子把它广播成 `f:名字:72.35` |
| `item:rocket` / `item:none` | **道具赛（11/10）** 你拿到了一个道具：`boost`、`shield`、`oil`、`rocket`、`bolt`、`police` 之一（比赛和大厅练习时骑过道具箱）。道具不会自己用，要板子发 `use`。用掉或者丢了以后发 `item:none` |
| `tx:<无线消息>` | **道具赛** 请板子把冒号后面的内容原样用无线发出去（`radio.send(msg[3:])`），和 `rx:` 正好相反。你用的道具要告诉同组的人时发，例如 `tx:i:AMY:rocket:BEN:3`。同一条发 3 次，间隔 0.15 秒（无线会丢包） |
| `hit:rocket` | **道具赛** 你被这个道具打中了：`rocket`、`bolt`、`police`，或者骑上了一滩 `oil`（骑上去的时候才发） |
| `blocked:rocket` | **道具赛** 你的护盾（`shield`）挡掉了这个道具 |

键盘对应：`F` 出拳，`R` 按铃，`E` 加速，`T` 卡通模式开/关，`Q` 特技（v0.3；外壳关掉键盘时这些键都不起作用，板子发的 `trick` 照样有效）。

**跳台和缺口（v0.3）：**
- 路上会出现跳台（小跳台、带平台的高跳台），骑上去自然升高，过了台边就飞起来，在空中能少量转向，落在路上或者另一个跳台上。飞行轨迹上挂着一串礼物，只有飞起来才拿得到。
- 有的路段有缺口（河湾、高架步道尽头）：在地上骑进去会掉下去，显示 SPLASH!（水）或 WHOOPS!（落空），这一局结束，板子收到 `crash`。飞过去就没事，落在缺口里一样会掉下去。缺口前面一定有跳台。
- 跳台手感（11/9）：骑上斜面会掉一点速度，用台边的速度起飞；离台边不到约 0.25 秒时按 `A`（`jp`）是"起跳"（屏幕上出现 POP!），飞得更高；更早按还是像以前一样，从斜面上普通跳。重重落地会掉速度（最多 20%），落在往下的桥面上很顺；空中做完特技、来得及摆正再落地，不掉速度，还会快一点。消息和顺序都不变。
- 一次飞行的消息顺序：`air:1` → （特技）→ `air:0` → `land:ok` 或 `land:trick`。这几条很少（几秒最多一次），V1 的串口缓冲够用。被追时按住 `S` 刹车就是靠边停车。

**警察消息的顺序和频率（11/8）：**
- 一局因为警察结束时，`arrested` 或 `busted` 总是**最后一条**，前面一定有 `crash`；正在追的话还会有 `heli:0`（直升机在的话）和 `chase:0`。所以"收到 `crash` 显示哭脸、收到 `busted` 显示别的"这种写法，最后留在屏幕上的是 `busted` 的。被追时撞到别的东西：`crash`、`heli:0`、`chase:0`，没有 `busted`。
- 甩掉警察时的顺序是 `wanted:0`、`chase:0`、`lost`。
- `cop:` 每秒最多 3 条，`inc:` 两条之间至少隔 0.15 秒（5 星时一次两个靶圈会连着发两条），其他警察消息很少，发生时马上发。加上 `spd:` 和 `warn:`，V1 的串口缓冲也够用。
- 第一课的程序不认识这些消息，会直接跳过，照样能玩。

**狂发没用（11/8 加的规则，数值在 `GameTuning` 的 "Punch and bell limits"）：**
- 出拳：拳头伸出去时转向只剩 30%（一只手离开车把）；最多连出 3 拳，然后 `tired`；打空扣 5 分，打中加 15 分；结算显示命中率。
- 按铃：冷却 1 秒；5 秒内按超过 3 次，行人 3 秒内不理你（头上冒"…"）。
- 卡通模式：每撞飞一个人花 1 个礼物；没有礼物时撞人就是撞车。
- 加速：冷却 6 秒。
- 最好的写法是收到 `warn:` 再出手，而不是放进 forever 里一直发。（`B` 在所有提示里都是板子上的刹车键，所以按铃不用 B）。

**场景消息（v0.3）：**
- `zone:` 只有游戏发，板子发了游戏不理（网页的串口监视器会提示"这是游戏发的消息"）。`say:zone:uwa` 也不行（带冒号）。
- 主题里只有一个场景时没有交界，只在开局发一次。
- 积木"when entering [Kings Park]"，或者"when the game says"里的 `zone:kingspark`，生成的都是一个 `elif msg == "zone:kingspark":` 分支，V1 也放得下。
- 开局画面显示出发场景（"Start: UWA"）。键盘开着时按数字键 1～7 换出发场景（老师演示用）；键盘关掉时（只用 micro:bit）不提数字键，按了也没用。默认出发场景在 `GameTuning.startDistrict`。
- 学生用板子选出发场景：`start:<id>`（11/9）。数字键和 `start:` 改的是同一个设置，谁后到听谁的。刷新网页后回到默认的 UWA。

**无线竞速（v0.4，11/9）：** 没有服务器，micro:bit 的无线就是网络（方案和课堂安排见 `docs/radio-race.md`）。代码在 `Messages.cs`（`race`、`rx`、`pos:`、`fin:`）、`RadioMessage.cs`（`rx:` 里面的三种消息）和 `RaceDirector.cs`。
- `rx:` 里面游戏认的三种无线消息（每条都是完整状态，丢一条没关系；大小写不敏感，冒号两边可以有空格）：

  | 无线消息 | 意思 | 格式不对 |
  |---|---|---|
  | `p:AMY:1234:-2` | AMY 骑到 1234 米，车道 -2 米（允许小数） | 丢掉，不报错 |
  | `f:AMY:72.35` | AMY 冲线了，用时 72.35 秒（只在比赛中和结算画面上算，同一场只算第一条） | 丢掉 |
  | `go:4821:uwa:2000` | 开始比赛：种子 1～99999，出发场景（`zone:` 的 id，不认识就用 `uwa`），米数 300～5000；超出范围就截断 | 丢掉 |

- 游戏的几个状态：
  - **普通模式**：没收到过 `race:`，或者 10 秒没收到了。和以前完全一样，不发 `pos:`。
  - **大厅**：屏幕上显示 `RACE 12 · YOU: AMY` 和最近 3 秒收到过 `p:` / `f:` 的人，名字后面的信号格按每秒收到几条算（大厅里正常是每秒 1 条）。提示 "Waiting for the race to start (go)"。按 A 只是练习骑。
  - **倒数**：在大厅或结算画面收到 `rx:go:…` 就倒数 3、2、1，然后开始。路、假拐弯都用 `go:` 的种子，从 `go:` 的出发场景出发，所以同组每台电脑上的路一模一样。倒数和比赛中再收到 `go:` 一律不理（发令程序 0.5 秒内连发 5 次，只有第一条算；自己的板子收不到自己发的无线，所以发令的那台电脑也是从 `rx:go:` 开始）。
  - **比赛**：屏幕顶部是赛程条（起点到终点，每人一个点，自己的最大），右上角是实时名次 "2nd / 5" 和用时。别人画成"幽灵车"：自己颜色的车和名字牌，放在他们的距离和车道上，不会和你相撞；两条 `p:` 之间按估计的速度往前推。超过 2 秒没消息变灰（"signal lost"），超过 10 秒去掉；最多画最近的 8 个，赛程条上画所有人。
  - **冲线**：在 `go:` 的米数处有 FINISH 拱门。过线后显示名次和用时，开始发 `fin:`。自己冲线 30 秒后，或者同组所有人都冲线以后（至少 3 秒），显示结算画面（领奖台）。结算画面上按 A 回到大厅；下一个 `go:` 开始下一场。
- 比赛模式里（大厅也算）：不理会改路的 `do:` 事件（大家的路必须一样）、`start:`（出发场景由 `go:` 决定）；没有卡通模式；加速 `bo` 照常。v1（11/9）不理所有 `do:`，也没有警察；**11/10 起警察类的 `do:` / `open:` 照常执行**，见下面"道具赛"一节。
- **撞车不结束比赛**：罚停 3 秒（板子照常收到 `crash`），然后在原地继续骑，屏幕上显示 "+3 s"。掉进缺口的话从缺口后面继续。
- **可疑数据**：两条 `p:` 之间前进的距离超过 最高速度 × 秒数 × 1.5 + 20 米，就把这个人标成 "?"，这条位置不用（有人发 `p:AMY:99999`）。冲线时间比最高速度还快的 `f:` 也标 "?"。带 "?" 的人在结算表上排在最后。用这个讨论冒充和信任。
- 一条无线消息最多 29 个字符（`radio.send` 的限制减去头）：`go:99999:canningbridge:5000` 是 27 个，5 个字母的名字加 5 位数的距离也放得下。

**道具赛（无线竞速 v2，11/10）：** 像马里奥赛车那样的道具。玩法、每个道具的效果、道具箱的位置、按名次的概率表都在 `docs/item-race.md`，这里只列消息。
- USB 上的五条消息在上面两张表里：`item:` / `hit:` / `blocked:` / `tx:`（游戏 → 板子）、`use`（板子 → 游戏）。
- 无线上多了 `i:`。内容由游戏写好，用 `tx:` 让自己的板子发出去；别人的板子收到后照常用 `rx:` 转给自己的游戏（`rx:i:AMY:rocket:BEN:3`），效果由被打中的那台电脑自己算：

  | 无线消息 | 意思 |
  |---|---|
  | `i:AMY:rocket:BEN:3` | AMY 的 rocket 打 BEN。最后的 3 是 AMY 的道具序号（0～9 循环） |
  | `i:AMY:police:BEN:4` | AMY 让警察去追 BEN |
  | `i:AMY:bolt:5` | AMY 的闪电：除了 AMY，同组所有人减速 |
  | `i:AMY:oil:1234:-2:6` | AMY 在 1234 米、-2 米车道上留了一滩油 |

  - 最长 22 个字符，在 29 个字符的上限以内。
  - 同一条发 3 次（`tx:` 给 3 次）。收的人按（发的人，序号）去重：最近 20 秒内见过就不理；发的人是自己的名字也不理。
  - 目标不是自己的 `rocket` / `police` 只在画面上给个提示，不产生效果。格式不对就丢掉，不报错。
- 转发 `tx:` 的代码和 `pos:` / `fin:` 放在一起，不用新积木：积木 "send my position by radio" 生成 `elif send_position and msg.startswith("tx:"): radio.send(msg[3:])`，`microbit/race.py` 里也有同样的一段。11/9 刷的旧程序不认识 `tx:`：能被打中，但自己的攻击发不出去，重新发一次代码就好。
- **比赛模式里的 `do:` / `open:`**（v1 不理所有 `do:`，所以 "on start → set the wanted stars to 5" 在比赛里不起作用）现在分两类：
  - 只影响自己的警察事件照常执行：`chase`、`stars:N`、`heli`、`calm`。大厅练习时也有效。等于给自己加难度。
  - 会改路的事件仍然不理：`turn`、`car`、`slowcar`、`roadworks`、`police`（拦路）、`crossing`、`manhole`、`ramp`。大家的路必须一样。屏幕上提示 "not in race mode"。
  - 比赛里有警察以后：被抓（`arrested`）、被撞或被狙（`busted`）都不结束比赛，和撞车一样罚停 3 秒，然后通缉清零。照常发 `arrested` / `busted` / `wanted:0` 给板子。
  - `open:`（每一局开头的事件）在比赛里同样处理：警察类的在每场比赛开始时执行。

### 学生代码必须先攒到换行再处理

MicroPython 的 `uart.readline()` 不会等一整行到齐，有多少字节就返回多少。2026-11-05 在模拟器里实测：`crash` 被读成了 `cr` 和 `ash` 两半。真板子出现的概率小一些，但也会有。所以起步代码统一用下面这个函数（已在模拟器里验证）：

```python
buf = ""

def messages():
    # uart.readline() can return half a line, so collect bytes until a newline arrives.
    global buf
    out = []
    if uart.any():
        data = uart.read()
        if data:
            buf += str(data, "utf-8")
            while "\n" in buf:
                line, buf = buf.split("\n", 1)
                out.append(line.strip())
            if len(buf) > 100:
                buf = ""
    return out
```

主循环里写 `for msg in messages(): ...`。另外别忘了 `uart.init(baudrate=115200)`。不带参数的 `uart.init()` 会把波特率改成 9600，游戏就收不到了。

## 无线竞速：网页的串口监视器和模拟器（11/9）

消息本身见 `docs/radio-race.md` 的"实现约定"，游戏怎么处理由游戏这边写在本文的消息表里。这里只写网页外壳怎么显示、模拟器里怎么测：

- `race:AMY:12` 每秒来一次，监视器只在名字或组号变了时记一行 "joins race 12 as AMY"。名字的规则和游戏一样（去掉字母、数字以外的字符，转大写，最多 5 个），所以 `race:amy!:12` 和 `race:AMY:12` 算同一个。空名字、组号超出 0～255、少了组号，显示黄色"格式不对"，并提示 `race:AMY:12` 的写法。
- `rx:` 行照常一条一条转给游戏，但监视器里合并成每秒一行："radio: 14 messages/s from AMY, BEN, CHLOE"。
  - 不是 `p:`、`f:`、`go:` 的内容也算进去，并举一个例子（`· 2 others, e.g. "hello"`），提示游戏只读这三种。
  - `rx:go:…` 只记一次（发令板连发 5 次）："radio: go! A race from UWA, 2000 m (road number 4821)"。
  - `rx:f:…` 每人记一次："radio: BEN finished in 72.35 s"。
- 游戏发给板子的 `pos:` / `fin:` 照常写进板子，监视器每秒只显示最新一条，后面注明这一秒发了几条。
- 板子自己打印 `pos:…`、`fin:…`（这是游戏发的）或者 `p:…`、`f:…`、`go:…`（这些要用 `radio.send` 发），监视器照常显示这一行，并给出提示。
- `ValueError: received packet is not a string`：同组有板子发了不是文字的包（MakeCode 或 `send_bytes`）。积木生成的代码和 `microbit/race.py` 会跳过这种包，不会停；学生自己写的代码没处理时程序会停，监视器提示换一个组号。
- 模拟器模式里有 **Robot racers**（三个机器人对手）和 **Send go**，见 `docs/bridge.md` 的"机器人对手"；模拟器的 `radio_output`（学生程序 `radio.send` 出去的）也在监视器里每秒汇总一行。

## 道具赛：网页的串口监视器和模拟器（11/10）

消息见上面"道具赛"一节。这里只写网页外壳怎么显示、模拟器里怎么测：

- 游戏发给板子的 `item:`、`hit:`、`blocked:` 显示成游戏的行，后面带一句说明。例如 `item:rocket` 后面是 "you got an item: nothing happens until your program says use"，`item:none` 后面是 "you have no item now (used or lost)"。
- `tx:` 游戏在 0.3 秒内说 3 次，3 次都写进板子，监视器只显示一次（同一行 1 秒内不重复显示），后面注明板子会用无线把它发出去。
- 板子发的 `use` 是认识的命令，不当成学生的 print。外壳记得游戏最后发给这块板的 `item:`：
  - 手里有道具：记一行 "uses its item: rocket"。程序按住按钮时每一轮都发，所以每秒最多一行。
  - 手里没有：提示一次 "use: no item to use"，说明要先在比赛里骑过道具箱。游戏下一次发 `item:` 之前不再提示；道具刚用掉（刚收到 `item:none`）的 2 秒内也不提示。
- `rx:i:…` 算进每秒一行的无线汇总，每个道具另外记一行："radio: AMY used rocket on BEN"、"radio: AMY dropped oil at 1234 m"、"radio: AMY used bolt"。
  - 同一条来 3 次只记一次：和游戏一样，（发的人，序号）20 秒内见过就不再记。
  - 目标是这块板自己的比赛名字（它发的 `race:` 里的名字）时，后面标 "that is you!"。
  - 格式不对的 `i:` 算进汇总里的 "other"，并举它做例子。
- 板子自己打印 `item:…`、`hit:…`、`blocked:…`、`tx:…`（这些是游戏发的），或者 `i:…`（这要用 `radio.send` 发，内容由游戏写），监视器照常显示这一行，并给出提示。
- 模拟器模式：机器人对手每 20～40 秒对你用一次 `rocket` 或 `bolt`，见 `docs/bridge.md` 的"机器人对手"。模拟器里的程序用无线发出 `i:` 时（`radio_output`），监视器记一行 "radio: you used rocket on BOT2"。
